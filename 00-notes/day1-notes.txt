

What Makes Web UI
---------------------

UI -> data + style + interaction
Web-UI -> HTML + CSS + JS with browser's APIs ( DOM, fetch, etc.)


how to run javascript programs?
-------------------------------

-> using javascript engine 

browser has a built-in javascript engine
------------------------------

1. chrome -> v8 ( c++ )
2. firefox -> rhino ( java ) | spidermonkey ( c++ )
3. safari -> nitro ( c++ )
4. edge -> chakra ( c++ )

non-browser javascript engine
------------------

1. node.js -> v8 ( c++ )
2. jvm -> rhino ( java ) | nashorn ( java )
....

Note: javascript engines implemented based on ECMAScript standard ( ECMA-262 )


why we need javascript programs with HTML-page?
--------------------------------------

using browser's APIs, we can use JS to manipulate HTML-page dynamically.

browser's APIs ( DOM, Fetch, etc..) -> w3c recommendations 

browser vendors implement these APIs in their browsers, 
abstracted as javascript objects and methods.

usign DOM ( Document Object Model ) 
------------------------------------
-> to create/retreive/update/delete HTML elements dynamically 
-> to listen to user events and respond to them
-> to change elements' data/style dynamically

using XHR ( XMLHttpRequest ) or Fetch API
---------------------------------------------
-> to communicate with server asynchronously 


using setTimeout() and setInterval()
--------------------------------------
-> to do any action on timer or interval basis

...
https://developer.mozilla.org/en-US/docs/Web/API

how things work in browser?
------------------------------

e.g chrome browser
--------------------

1. javascript engine ( v8 ) ( ECMAScript standard )
    -> single-call-stack
    -> heap
2. browser's APIs ( DOM, Fetch, etc.. ) ( w3c recommendations ) - 
    -> implemented by browser vendors
    -> abstracted as javascript objects and methods
3. Event-Queue - 
    -> stores all the events ( user events, server response events, timer events, etc.. )
4. Event-Loop - 
    -> continuously checks the call-stack and event-queue
    -> if call-stack is empty, it takes the first event from event-queue and pushes it to call-stack for execution

Learning HTML
-----------------

types of HTML elements
----------------------

1. inline elements
    -> do not start on a new line
    -> do not take full width of the page
    -> e.g <span>, <a>, <b>, <i>, <img>, <input>, etc..
2. block elements
    -> start on a new line
    -> take full width of the page
    -> e.g <div>, <p>, <h1>, <h2>, <h3>, <ul>, <ol>, <li>, etc..

 --------------------------------

1. link elements
    -> <a> ( anchor ) - to create hyperlinks
    -> <link> - to link external resources ( css, fonts, etc.. )
2. text elements
    -> <p> - paragraph
    -> <h1>, <h2>, <h3>, <h4>, <h5>, <h6> - headings
    -> <span> - inline text container
3. list elements
    -> <ul> - unordered list
    -> <ol> - ordered list
    -> <li> - list item
    -> <dl> - description list
    -> <dt> - description term
    -> <dd> - description definition
4. form elements
    -> <form> - form container
    -> <input> - input field
    -> <textarea> - multi-line text input
    -> <button> - clickable button
    -> <select> - dropdown list
    -> <option> - dropdown list option
    -> <label> - label for form elements
5. media elements
    -> <img> - image
    -> <audio> - audio player
    -> <video> - video player
    -> <canvas> - drawing area
    -> <svg> - scalable vector graphics
6. table elements
    -> <table> - table container
    -> <tr> - table row
    -> <td> - table cell
    -> <th> - table header cell
    -> <thead> - table header section
    -> <tbody> - table body section
    -> <tfoot> - table footer section

7. semantic elements 
    -> <header> - header section
    -> <footer> - footer section
    -> <main> - main content section
    -> <section> - section of content
    -> <article> - self-contained content
    -> <aside> - sidebar content
    -> <nav> - navigation links
