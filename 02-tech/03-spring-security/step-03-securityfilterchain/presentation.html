SecurityConfig.java

The ONE file that replaces auto-configuration

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {

        http
            // 1. Authorization rules
            .authorizeHttpRequests(authorize -> authorize
                // Public pages
                .requestMatchers("/", "/login", "/logout").permitAll()
                .requestMatchers("/css/**", "/webjars/**").permitAll()
                .requestMatchers("/h2-console/**").permitAll()
                // Everything else needs login
                .anyRequest().authenticated()
            )
            // 2. Form login
            .formLogin(withDefaults())
            // 3. HTTP Basic
            .httpBasic(withDefaults())
            // 4. Allow H2 Console frames
            .headers(h -> h.frameOptions(f -> f.sameOrigin()))
            // 5. Disable CSRF for H2 Console
            .csrf(c -> c.ignoringRequestMatchers("/h2-console/**"));

        return http.build();
    }
}

authorizeHttpRequests() Deep Dive

The most important DSL method — WHO can access WHAT

// Authorization rules are evaluated
// TOP-TO-BOTTOM, FIRST MATCH WINS

.authorizeHttpRequests(auth -> auth

  // Exact path match
  .requestMatchers("/")
    .permitAll()

  // Ant-style wildcards
  .requestMatchers("/css/**")
    .permitAll()

  // HTTP method + path
  .requestMatchers(HttpMethod.GET, "/api/**")
    .permitAll()

  // Role-based (coming in later steps)
  .requestMatchers("/admin/**")
    .hasRole("ADMIN")

  // Catch-all - MUST be last!
  .anyRequest()
    .authenticated()
)

Authorization Methods

MethodMeaning
.permitAll()Anyone can access (no login)
.authenticated()Must be logged in
.hasRole("X")Must have role ROLE_X
.hasAuthority("X")Must have authority X
.hasAnyRole("X","Y")Must have any of these roles
.denyAll()Nobody can access
Order matters! anyRequest() must be LAST. Rules are checked top to bottom.

Lambda DSL (Spring Security 6.x)

The old chaining style vs the new lambda style

Old Style (deprecated)

// Spring Security 5.x style
// Deprecated in 6.x!

http
  .authorizeRequests()   // old method name!
    .antMatchers("/")    // old matcher!
      .permitAll()
    .anyRequest()
      .authenticated()
  .and()                   // chaining with and()
  .formLogin()
  .and()
  .httpBasic();

New Style (Spring Security 6.x)

// Lambda-based DSL
// Current best practice!

http
  .authorizeHttpRequests(a -> a  // lambda
    .requestMatchers("/")       // new!
      .permitAll()
    .anyRequest()
      .authenticated()
  )                             // no .and()!
  .formLogin(withDefaults())    // lambda
  .httpBasic(withDefaults());   // lambda
Always use the lambda style. The old .and() chaining and antMatchers() are deprecated in Spring Security 6+.

formLogin() vs httpBasic()

formLogin()

  • HTML login page at /login
  • POST username + password as form data
  • Creates a server-side session
  • Sends JSESSIONID cookie
  • Perfect for web apps (browsers)
// Browser submits:
POST /login
Content-Type: application/x-www-form-urlencoded

username=user&password=abc&_csrf=token

httpBasic()

  • No login page — uses HTTP header
  • Authorization: Basic base64(user:pass)
  • Credentials sent on every request
  • No session needed (stateless)
  • Perfect for APIs (curl, Postman)
// API client sends:
GET /api/events
Authorization: Basic dXNlcjphYmM=

// base64("user:abc") = "dXNlcjphYmM="

Fixing H2 Console Access

H2 Console uses iframes — Spring Security blocks them by default

Problem 1: X-Frame-Options

Default: X-Frame-Options: DENY
H2 Console uses <iframe> internally.
Browser refuses to render frames.

Problem 2: CSRF

H2 Console makes POST requests without CSRF tokens.
Spring Security rejects them with 403.

// Fix 1: Allow frames from same origin
http.headers(headers -> headers
  .frameOptions(frame ->
    frame.sameOrigin()  // was DENY
  )
);

// Fix 2: Disable CSRF for H2 paths
http.csrf(csrf -> csrf
  .ignoringRequestMatchers(
    "/h2-console/**"
  )
);

// Fix 3: Allow access without login
.requestMatchers("/h2-console/**")
  .permitAll()


// WARNING: Only for development!
// Never expose H2 Console in production!

Request Flow With Our Config

GET / (Welcome page)

Browser: GET / v [AuthorizationFilter] requestMatchers("/").permitAll() MATCH! → Access granted v DispatcherServlet → WelcomeController v 200 OK → index.html No login needed!

GET /events/ (Protected)

Browser: GET /events/ v [AuthorizationFilter] requestMatchers("/").permitAll() → no match anyRequest().authenticated() → MATCH! Not authenticated? → AccessDeniedException v [ExceptionTranslationFilter] Save /events/ → Redirect to /login v 302 → /login

withDefaults() vs Custom Lambda

You can pass defaults or customize each feature

Using Defaults

// Accept all default behavior
http
  .formLogin(withDefaults())
  .httpBasic(withDefaults())
  .logout(withDefaults());

// Equivalent to:
// formLogin(form -> {})
// Uses default /login page
// Uses default success/failure URLs

Custom Configuration

// Customize behavior with lambdas
http
  .formLogin(form -> form
    .loginPage("/custom-login")
    .defaultSuccessUrl("/dashboard")
    .failureUrl("/login?error")
  )
  .logout(logout -> logout
    .logoutUrl("/signout")
    .logoutSuccessUrl("/")
    .deleteCookies("JSESSIONID")
  );

// We'll customize these in later steps!
Tip: Start with withDefaults(), customize only when needed. Less code = fewer bugs.

Common Mistakes

anyRequest() Not Last

// WRONG! Compiler error:
.anyRequest().authenticated()
.requestMatchers("/").permitAll()
// Can't add rules after anyRequest!

// CORRECT:
.requestMatchers("/").permitAll()
.anyRequest().authenticated()

Forgetting Static Resources

// Login page loads but looks broken!
// CSS and JS are also protected!

// FIX: permit static resources:
.requestMatchers(
  "/css/**",
  "/js/**",
  "/webjars/**",
  "/images/**"
).permitAll()

Multiple SecurityFilterChain Beans

// If you define a SecurityFilterChain,
// auto-config is DISABLED.
// Your bean REPLACES the default one.
//
// Two beans without @Order?
// Ambiguous! Use @Order(1), @Order(2)

Trailing Slash Mismatch

// This does NOT match "/events/"
.requestMatchers("/events")

// Use pattern for both:
.requestMatchers("/events/**")
// or list both:
.requestMatchers("/events", "/events/")
