Step 01

Spring Security Auto-Configuration

"Add one dependency. Everything changes."

Use ← → to navigate

The Only Change

One dependency added to pom.xml. Zero Java code changed.

<!-- pom.xml -->
<dependencies>
    ...existing dependencies...

    <!-- ADD THIS ONE LINE -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-security</artifactId>
    </dependency>

    ...rest unchanged...
</dependencies>
This single dependency pulls in spring-security-web, spring-security-config, and spring-security-core — and Spring Boot auto-configures everything.

What Just Happened?

Spring Boot detected spring-security on the classpath and auto-configured:

Authentication

  • Generated a random password (printed to console)
  • Created a default user named user
  • Added a login page at /login
  • Added a logout endpoint at /logout
  • HTTP Basic auth also enabled

Protection

  • ALL endpoints require authentication
  • CSRF protection enabled on all POST/PUT/DELETE
  • Session fixation protection (new session on login)
  • Security headers added to all responses
  • Clickjacking protection (X-Frame-Options: DENY)

Default Login Page

Spring Security generates a complete login page at /login:

  • HTML form with username & password fields
  • CSRF token hidden field (auto-included)
  • POST to /login to authenticate
  • Error message on failed login
  • Redirect to original URL after success
Flow:
1. User visits /events
2. Not authenticated → redirected to /login
3. User logs in successfully
4. Redirected back to /events

Security Headers (Auto-Added)

Check DevTools → Network → Response Headers

HeaderValueProtection Against
X-Content-Type-Options nosniff MIME-type sniffing attacks
X-Frame-Options DENY Clickjacking (embedding in iframe)
Cache-Control no-cache, no-store Sensitive data cached by browser
X-XSS-Protection 0 Disabled (CSP is preferred now)
Strict-Transport-Security max-age=31536000 Downgrade attacks (HTTPS only)
Before: None of these headers existed. After: All added automatically by HeaderWriterFilter.

Behind the Scenes

What classes made this happen?

Spring Boot Auto-Config

// activate automatically:

@ConditionalOnClass(
  DefaultAuthenticationEventPublisher.class
)
class SecurityAutoConfiguration {
  // Creates UserDetailsService
  // if none exists
}

@ConditionalOnDefaultWebSecurity
class SpringBootWebSecurityConfiguration {
  // Creates default SecurityFilterChain
  // if none exists
}

What It Creates

// Equivalent to writing this yourself:

@Bean
public SecurityFilterChain filterChain(
    HttpSecurity http) {

  http
    .authorizeHttpRequests(auth ->
      auth.anyRequest()
          .authenticated()  // ALL urls
    )
    .formLogin(withDefaults()) // login page
    .httpBasic(withDefaults()); // basic auth

  return http.build();
}

CSRF Protection (Now Active)

What is CSRF?

Cross-Site Request Forgery: A malicious site tricks your browser into making requests to another site where you're logged in.

Attacker's site: <form action="http://bank.com/transfer" method="POST"> <input name="to" value="hacker"/> <input name="amount" value="10000"/> </form> <script>document.forms[0].submit()</script> Your browser sends your cookies! Bank thinks it's YOU making the request.

How Spring Security Prevents It

Every form gets a unique, unpredictable token. Server rejects requests without a valid token. 

<!-- Thymeleaf auto-adds this: -->
<form th:action="@{/events/new}">

  <!-- Hidden field auto-generated -->
  <input type="hidden"
    name="_csrf"
    value="x7Kp2mN..." />

  ...form fields...
</form>

// Attacker can't guess this token!
// Their forged form will be REJECTED
// with 403 Forbidden

What's Still Wrong?

Auto-config is great for getting started, but not production-ready:

Password Problem

Random password changes every restart. No way to share credentials. Not suitable for real users.

Single User

Only user exists. No roles, no admin vs regular user distinction. Everyone sees everything.

No Authorization

Once logged in, ALL pages accessible. /events/ (admin) and /events/my (user) not differentiated.

Key Takeaways

What We Learned

  • spring-boot-starter-security activates auto-config
  • ALL endpoints secured by default (deny-by-default)
  • Default login form + generated password
  • CSRF tokens auto-added to Thymeleaf forms
  • Security headers added to every response
  • Session fixation protection enabled

Key Classes

  • SecurityAutoConfiguration — triggers setup
  • SpringBootWebSecurityConfiguration — default chain
  • UserDetailsServiceAutoConfiguration — creates user
  • DefaultLoginPageGeneratingFilter — login page
  • CsrfFilter — CSRF protection
  • HeaderWriterFilter — security headers
