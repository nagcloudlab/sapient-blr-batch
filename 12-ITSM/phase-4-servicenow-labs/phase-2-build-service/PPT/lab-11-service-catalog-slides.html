Act 1 • The Critical Distinction

Service Request vs Incident

One of the most commonly confused concepts in ITSM.

AspectService RequestIncident
NaturePlanned, expectedUnplanned, unexpected
RiskLow / NoneVaries (can be critical)
Pre-approved?Yes (follows a model)No (needs investigation)
Example"Give me API access""The API is returning 500 errors"
GoalFulfill a known needRestore normal service
Tablesc_req_item (RITM)incident
ITIL 4: A service request is a request from a user that initiates a service action which has been agreed as a normal part of service delivery. It is pre-defined, pre-approved, and follows a standard fulfillment model.

Act 1 • The Lifecycle

REQ → RITM → SCTASK

Three tables, one lifecycle. Think of it as a shopping cart.

sc_request (REQ)              -- The shopping cart (overall request)
    |
    +-- sc_req_item (RITM)    -- Individual item ordered (one per catalog item)
            |
            +-- sc_task (SCTASK) -- Fulfillment step 1 (e.g., "Verify documents")
            +-- sc_task (SCTASK) -- Fulfillment step 2 (e.g., "Configure in UPI Switch")
TablePrefixLifecycle Rule
sc_requestREQDoes not close until all RITMs close
sc_req_itemRITMDoes not close until all SCTASKs close
sc_taskSCTASKAssigned to fulfillment groups; closed when work is done
REQ States:     Open --> Approved --> Closed Complete
RITM States:    Open --> Approved --> Work in Progress --> Closed Complete
SCTASK States:  Open --> Work in Progress --> Closed Complete
Approval:       Requested --> Approved / Rejected

Act 1 • Architecture

Service Catalog Architecture

Service Catalog (sc_catalog)
    |
    +-- Category: Access & Onboarding
    |       +-- Catalog Item: Request API Access
    |       |       +-- Variables (API Name, Environment, Purpose)
    |       |       +-- Catalog Client Scripts (Production warning)
    |       |       +-- Approval Definition (conditional: Prod only)
    |       |       +-- Execution Plan (1 SCTASK)
    |       +-- Catalog Item: Request Team Member Access
    |
    +-- Category: Merchant Services
    |       +-- Catalog Item: Request Merchant Onboarding
    |               +-- Variables (Merchant Name, Business Type, TPS...)
    |               +-- Approval (sequential: Manager then Tech Lead)
    |               +-- Execution Plan (2 SCTASKs, sequential)
    |
    +-- Category: Report an Issue
    |       +-- Record Producer: Report UPI Payment Issue
    |               (Creates an Incident, not an RITM!)
    |
    +-- Category: Infrastructure Requests
    +-- Category: Compliance & Security
Record Producer = looks like a catalog item to the user, but creates a record on a different table (e.g., Incident, Problem) instead of an RITM.

Act 2 • Dynamic Forms

Catalog Client Scripts & UI Policies

Client Script: Production Warning

When user selects "Production" on Request API Access:

function onChange(control, oldValue,
                  newValue, isLoading) {
  if (isLoading) return;
  if (newValue === 'production') {
    g_form.showFieldMsg(
      'target_environment',
      'Production access requires
       Tech Lead approval.',
      'warning'
    );
  } else {
    g_form.hideFieldMsg(
      'target_environment');
  }
}
