Act 1 • The Gap

ServiceNow is blind to production

What we have built (Labs 07-11)

  • CMDB with 12 CIs and 21 relationships
  • Business Service: UPI Payment Processing
  • SLAs: P1 = 1 hr resolve, P3 = 8 hrs
  • Knowledge Base articles for known issues
  • Assignment groups and escalation paths

What is missing

  • No live monitoring connected
  • Incidents are created manually
  • Nobody knows a service is down until a user calls
  • MTTD (Mean Time to Detect) = hours, not seconds
  • SLA clocks do not start until someone notices
The CMDB is a map. But without monitoring, nobody sounds the alarm when a road collapses.

Act 1 • The Pipeline

Prometheus to ServiceNow

The 4-stage alert pipeline that closes the loop.

                                 +---------------------+
                                 |    ServiceNow PDI    |
                                 |  (Incident created)  |
                                 +---------^-----------+
                                           | REST API
                                 +---------+-----------+
                                 |    Snow Bridge       |
                                 |  (Webhook --> SNOW)   |
                                 +---------^-----------+
                                           | webhook
                                 +---------+-----------+
                                 |    AlertManager      |
                                 |  (Route alerts)      |
                                 +---------^-----------+
                                           | alert rules
+----------------+  scrape   +-------------+---------------+
|  Grafana       |<----------|      Prometheus              |
|  Dashboard     |           |  (Scrape + Evaluate)         |
+----------------+           +--+--------------------+------+
                                |                    |
                     +----------+------+  +----------+--------+
                     | UPI Transaction |  | UPI Settlement     |
                     | Service (:8081) |  | Service (:8082)    |
                     +-----------------+  +--------------------+
Closed loop: Metrics scraped --> threshold breached --> alert fires --> webhook sent --> incident created --> CI attached --> SLA starts. All automatic.

Act 2 • Inject Chaos

Scenario A: 80% failure rate (P1 Critical)

T+0s Run ./chaos/inject.sh → choose 1 (Enable 80% failure rate)
T+10s Grafana failure rate gauge climbs from 0% to ~80% (turns red)
T+30s Transaction chart shows red (failed) bars dominating. Settlements cascade-fail.
T+60s Prometheus fires UpiHighTransactionFailureRate alert
T+62s AlertManager routes to Snow Bridge via webhook
T+63s Snow Bridge creates P1 incident in ServiceNow: INC00XXXXX
Check ServiceNow: Incident > All → find "[AUTO] UPI transaction failure rate above 50%". Priority: 1 - Critical. Category: Software. Assignment group: Platform Engineering.

Act 2 • Manage

Manage the incident in ServiceNow

Step 1 Assign the incident to Ravi Kumar (Platform Engineering)
Step 2 Change state to In Progress
Step 3 Add work note: "Investigating high failure rate. Checking chaos/config status."
Step 4 In chaos script, choose 4 (Disable all chaos) — failure rate drops to 0%
Step 5 Alerts auto-resolve in ~2 minutes. Snow Bridge adds resolution note.
Step 6 Back in ServiceNow: state → Resolved. Resolution: "Configuration corrected."
Closed loop: Alert fires → incident created → fix applied → alert resolves → incident closed. No human had to detect the problem.

Key concepts from this lab

ConceptDefinition
ObservabilityUnderstanding system state from external outputs (metrics, logs, traces)
PrometheusOpen-source metrics collection and alerting toolkit
AlertManagerHandles alert deduplication, grouping, routing, and silencing
WebhookHTTP callback that delivers real-time notifications
Chaos EngineeringDeliberately injecting failures to test system resilience
MTTDMean Time to Detect — how fast you identify an incident
MTTRMean Time to Resolve — how fast you fix an incident
Closed-loopAlert fires → incident created → fixed → alert resolves → incident closed
