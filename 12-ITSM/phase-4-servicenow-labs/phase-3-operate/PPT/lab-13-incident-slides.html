Act 1 • Core Concept

What is an Incident?

An unplanned interruption or reduction in quality of an IT service.

Incident (this lab)

  • Something is broken right now
  • Goal: restore service as fast as possible
  • Reactive — triggered by alert or user report
  • Example: "UPI payments failing at 80% rate"
  • Measure: MTTR (Mean Time to Resolve)

Problem (Lab 14)

  • Something keeps breaking
  • Goal: find root cause, prevent recurrence
  • Proactive — opened after pattern detected
  • Example: "WHY do UPI payments keep failing?"
  • Measure: reduction in recurring incidents
ITIL distinction: Incident Management restores service. Problem Management prevents future incidents. They are separate practices that work together.

Act 1 • Priority

The Priority Matrix: Impact x Urgency

Priority is auto-calculated in ServiceNow. You set Impact and Urgency; the system determines Priority.

                         Impact
                  1-High    2-Medium    3-Low
Urgency  1-High    P1          P2        P3
         2-Medium  P2          P3        P4
         3-Low     P3          P4        P5

Priority:
  P1 = Critical    "All UPI payments down"          SLA: 1 hour
  P2 = High        "Payment gateway degraded"       SLA: 4 hours
  P3 = Moderate    "Settlement batch slow"           SLA: 8 hours
  P4 = Low         "Single user printer issue"       SLA: 24 hours
  P5 = Planning    "UI font looks wrong"             SLA: 72 hours
Impact = how many users / services are affected. Urgency = how quickly must it be resolved. A P1 incident must never be manually set — the matrix ensures consistency.

Act 2 • Lifecycle

Full incident lifecycle

New Incident created. SLA clock starts. Awaiting assignment.
In Progress Assigned to agent. Investigation begins. Work notes added.
On Hold Waiting for vendor, user, or external input. SLA clock pauses.
In Progress Response received. Work resumes. SLA clock resumes.
Resolved Fix applied. Resolution code + notes documented. User notified.
Closed User confirms fix. Close code + notes. Incident complete.
Practice this now: Open the VPN P1 incident. Walk it through every state. At each transition, add a work note explaining what happened. Review the Activity Stream at the end — that is your audit trail.

Act 2 • SLA

The SLA clock is always ticking

SLA timers on your P1 incident

  • Response SLA: 15 minutes to acknowledge
  • Resolution SLA: 1 hour to resolve
  • Timer starts at incident creation
  • Timer pauses when state = On Hold
  • Timer resumes when back to In Progress
  • Breach = red flag, escalation triggered

SLA breach = escalation. If P1 is not resolved in 60 minutes, the incident auto-escalates to the manager. This is why accurate priority matters.
