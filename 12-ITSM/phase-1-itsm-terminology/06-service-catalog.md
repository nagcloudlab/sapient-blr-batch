# Section 6: Service Catalog

## What is a Service Catalog?

A structured list of **all IT services available** to users, with details on what they get, how to request it, and what to expect.

Think of it as: **"The menu at a restaurant."** You don't walk into the kitchen and ask the chef -- you look at the menu, pick what you want, and place an order.

---

## Without vs With a Service Catalog

| Without | With |
|---|---|
| "Who do I email for prod access?" | Click "Production Access" in the catalog -> auto-routed |
| "How long will it take?" | Catalog says: "SLA: 4 hours" |
| "What do I need to provide?" | Form asks: environment, role, justification, manager |
| "Is this even available?" | If it's in the catalog, it's available |

## UPI Example: NPCI's Service Catalog

### For Banks (External Catalog)

| Service | Description | SLA | How to Request |
|---|---|---|---|
| **Bank Onboarding** | Connect your bank to UPI network | 30 days | Submit compliance docs + API integration form |
| **TPS Limit Change** | Increase/decrease your transaction rate limit | 1 business day | Portal request + capacity review |
| **Settlement Reports** | Daily/monthly settlement data | Auto-generated by 6 AM | Self-service download from portal |
| **Dispute Filing** | Raise a dispute for a failed transaction | Acknowledgment: 1 hour | API call or portal submission |
| **PSP App Registration** | Register a new UPI app (like PhonePe) | 45 days | Compliance + security audit + sandbox testing |

### For Internal Teams (Internal Catalog)

| Service | Description | SLA | Approval |
|---|---|---|---|
| **Production Access** | Read/write access to prod systems | 4 hours | Manager + Security Lead |
| **New Environment** | Staging/QA environment setup | 2 business days | Infra Lead |
| **Monitoring Dashboard** | Custom Grafana dashboard for your service | 1 business day | Self-service template |
| **VPN Credential Reset** | Reset your VPN access | 30 minutes | Auto-approved |
| **License Request** | New software license (IDE, monitoring tool) | 3 business days | Manager + Procurement |

## Anatomy of a Catalog Item

Every item in the catalog has:

```
+--------------------------------------------------+
| Service: Production Database Access               |
|--------------------------------------------------|
| Description: Read-only access to UPI transaction |
|              database for debugging               |
|                                                   |
| Category:    Access Management                    |
| Owner:       Database Administration Team         |
|                                                   |
| Who can request: Any NPCI engineer (L2+)          |
|                                                   |
| What you need to provide:                         |
|   - Database name                                 |
|   - Justification                                 |
|   - Duration (temporary/permanent)                |
|                                                   |
| Approval: Manager + DBA Lead                      |
| SLA: 4 hours                                      |
| Cost: Internal (no charge)                        |
+--------------------------------------------------+
```

## Two Views of the Catalog

| View | Audience | Shows |
|---|---|---|
| **Business Service Catalog** | End users, banks, partners | What services are available, SLAs, how to request |
| **Technical Service Catalog** | IT teams internally | Dependencies, infrastructure details, support teams, runbooks |

Same service, different depth:

```
Business view:
  "UPI Payments -- send money instantly, 99.9% uptime"

Technical view:
  "UPI Txn Engine v4.1 -- runs on K8s cluster-A, depends on
   Kafka, Oracle DB, and PSP gateway. On-call: platform-team.
   Runbook: wiki/upi-txn-engine"
```

## Key Takeaway

> The Service Catalog is the **single source of truth** for "what can I get, how do I get it, and how long will it take?"
>
> Without it, users send random emails and Slack messages. With it, every request is **standardized, trackable, and SLA-bound**.
