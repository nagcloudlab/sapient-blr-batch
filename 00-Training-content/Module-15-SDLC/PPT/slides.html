MODULE 15 - SDLC FUNDAMENTALSWHY IT MATTERS
SDLC Is the Safety System for Change
Definition

Software Development Life Cycle (SDLC) is a structured process for planning, creating, testing, deploying, and maintaining software applications.

By the end of today, you can:
Map 7 SDLC stagesCompare delivery methodsRead BRD / SRS / FRDConnect SDLC to STLCChoose the right environmentPlan a safe sustain change
Sustain lens: You may inherit software in maintenance, but every safe fix still passes through analysis, design, build, test, and deployment.

Activity: The Cost of a Bug
GROUP ACTIVITY15 minutes | Groups of 4-5
Scenario
FoodExpress has a bug: the delivery fee calculation is wrong. Instead of charging Rs 40 for orders under Rs 300, it charges Rs 0. This bug has been in production for 2 weeks.
Discuss in Your Group
  • Q1: At which SDLC stage should this bug have been caught?
  • Q2: What types of testing would have caught it? (unit, integration, UAT?)
  • Q3: Estimate the financial impact (assume 5,000 orders/day, 60% under Rs 300)
  • Q4: What process changes would prevent this in the future?
  • Q5: As a sustain engineer, what is your immediate action plan?
Expected Discussion Points
QuestionKey Points
StageShould be caught in Testing (unit + integration)
Testing typesUnit test for fee calculation, integration test for order flow
Financial impact5000 x 60% x Rs 40 x 14 days = Rs 16,80,000 (~$20K)
PreventionAdd boundary tests, code review checklist, staging smoke tests
Action planHotfix, add regression test, RCA document, post-mortem

Each Iteration (Spiral)
QuadrantActivityFoodExpress Example
1. PlanningDefine objectives, identify alternativesIteration 1: Build ordering prototype
2. Risk AnalysisIdentify and mitigate risks, build prototypeRisk: Payment integration may fail -- build payment prototype
3. EngineeringDevelop and test the productBuild order + payment integration, test
4. EvaluationCustomer review, plan next iterationDemo to stakeholders, gather feedback
When to Use Spiral
  • Large, complex, high-budget projects
  • Requirements are unclear or expected to change
  • Risk management is critical
  • Customer needs frequent evaluation checkpoints
Key Difference: Spiral is risk-driven (prototype to reduce risk), while Agile is feature-driven (deliver working features).

Key Takeaways
ConceptKey Lesson
SDLC StagesPlan -> Analyze -> Design -> Build -> Test -> Deploy -> Maintain -> Retire
Testing RiskBug cost increases 100x from requirements to production -- Knight Capital lost $440M in 45 min
WaterfallSequential, heavy documentation, fixed scope -- good for regulated environments
V-ModelEach dev phase paired with a test phase -- safety-critical, regulatory traceability
SpiralRisk-driven iterations with prototyping -- large, complex, high-risk projects
ScrumIterative sprints (2-4 weeks), roles (PO, SM, Team), ceremonies (standup, review, retro)
KanbanContinuous flow, WIP limits, visualize work -- ideal for sustain and ops work
DevOpsCulture + automation + measurement + sharing; CI/CD, IaC, monitoring
BRD/SRS/FRDBRD = business why, SRS = system what, FRD = functional how
STLCParallel to SDLC: requirement analysis -> test planning -> design -> execute -> close
EnvironmentsLocal -> Dev -> Staging -> Pre-Prod -> Prod; maintain parity, isolate data
Sustain ContextYou work in the Maintain phase; follow change management, add tests, document everything
