What is Helm?

Helm is a package manager for Kubernetes — think apt, yum, or npm but for K8s.

Templating Engine

Use Go templates to parameterize YAML manifests. One chart, many environments.

Package Management

Bundle all K8s resources into a single deployable unit called a Chart.

Release Management

Track deployments as Releases with history, upgrade, and rollback support.

Dependency Management

Charts can depend on other charts (e.g., your app chart depends on a PostgreSQL chart).

Key Points (Helm 3)

  • No Tiller — removed the server-side component (was in Helm 2)
  • Uses kubeconfig for auth (same as kubectl)
  • Release info stored as Secrets in the target namespace
  • Three-way strategic merge for upgrades
  • Improved security — no cluster-admin needed

Helm Templating

values.yaml

replicaCount: 1 image: repository: nagabhushanamn/todos-service tag: "9" service: type: NodePort port: 8080 nodePort: 30080 postgres: database: tododb user: postgres password: postgres hpa: enabled: true minReplicas: 1 maxReplicas: 5 cpuUtilization: 50

templates/deployment.yaml

apiVersion: apps/v1 kind: Deployment metadata: name: {{ .Release.Name }}-app spec: replicas: {{ .Values.replicaCount }} template: spec: containers: - name: {{ .Chart.Name }} image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}" ports: - containerPort: {{ .Values.service.port }} {{- if .Values.hpa.enabled }} resources: requests: cpu: 200m {{- end }}

Template Functions & Flow Control

Built-in Objects

# Release info {{ .Release.Name }} {{ .Release.Namespace }} {{ .Release.Revision }} # Chart info {{ .Chart.Name }} {{ .Chart.Version }} # Values from values.yaml {{ .Values.image.repository }}

Common Functions

# Default value {{ .Values.env | default "production" }} # Quote strings {{ .Values.name | quote }} # Base64 encode (for Secrets) {{ .Values.password | b64enc }} # Indent for YAML nesting {{ toYaml .Values.resources | indent 8 }}

Conditionals

{{- if .Values.hpa.enabled }} apiVersion: autoscaling/v2 kind: HorizontalPodAutoscaler ... {{- end }}

Loops

env: {{- range $key, $val := .Values.env }} - name: {{ $key }} value: {{ $val | quote }} {{- end }}

Named Templates (_helpers.tpl)

# Define {{- define "app.fullname" -}} {{ .Release.Name }}-{{ .Chart.Name }} {{- end }} # Use name: {{ include "app.fullname" . }}

Overriding Values per Environment

values-dev.yaml

replicaCount: 1 image: tag: "latest" service: type: NodePort hpa: enabled: false postgres: password: devpass

values-prod.yaml

replicaCount: 3 image: tag: "9" service: type: LoadBalancer hpa: enabled: true maxReplicas: 10 postgres: password: $PROD_DB_PASS

Deploy per Environment

# Development $ helm install todos-dev ./todos-app \ -f values-dev.yaml \ -n dev # Production $ helm install todos-prod ./todos-app \ -f values-prod.yaml \ -n prod # Override individual values $ helm install todos ./todos-app \ --set image.tag="10" \ --set replicaCount=2 # Combine: file + inline override $ helm upgrade todos-prod ./todos-app \ -f values-prod.yaml \ --set image.tag="11"

Helm Best Practices

Version Everything

Use semantic versioning for both version (chart) and appVersion (app) in Chart.yaml.

Use helm template

Always dry-run with helm template before deploying to catch errors early.

Secrets Management

Never commit secrets in values.yaml. Use helm-secrets plugin or external secret managers (Vault, AWS SM).

Use upgrade --install

Makes deployments idempotent — works for both first install and subsequent upgrades.

Keep Charts Generic

Design charts to be reusable. Environment-specific values go in separate values files.

Use _helpers.tpl

Define reusable named templates for labels, names, and selectors to stay DRY.

Pin Dependencies

Always pin chart dependency versions to avoid unexpected breaking changes.

Add NOTES.txt

Provide post-install instructions showing how to access the app after deployment.
