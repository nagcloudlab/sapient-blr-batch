## Presentation Structure (15 minutes)

### 1. Introduction (1 min)
- Team name and members
- Which bugs/tasks were assigned

### 2. Bug Fixes Demo (5 min)
_For each bug fixed:_

| Bug | What Was Wrong | How We Fixed It | Demo |
|-----|---------------|-----------------|------|
| #1  |               |                 | Live demo or screenshot |
| #2  |               |                 | Live demo or screenshot |
| #3  |               |                 | Live demo or screenshot |

### 3. Technical Deep Dive (3 min)
_Pick the most interesting or challenging fix and explain:_
- Root cause analysis (5 Whys if applicable)
- Why the bug existed in the first place
- How you found it
- Why your fix is correct (not just a workaround)

### 4. Challenges and Learnings (3 min)
- What was the hardest part?
- What would you do differently?
- What did you learn that applies to real sustain work?

### 5. Questions (3 min)
_Be prepared for questions like:_
- "What if the fix breaks something else?"
- "How would you test this in production?"
- "What monitoring would you add?"

---

## Preparation Checklist

- [ ] All fixes verified and working
- [ ] Screenshots captured for any non-live demos
- [ ] Fix report completed for each bug
- [ ] Presentation rehearsed (under 15 min)
- [ ] One team member ready to do live demo
- [ ] Others ready to answer technical questions
